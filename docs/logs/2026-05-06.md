# Updates — 2026-05-06

## What We Did

### Phase 6 — Mutual TLS Client Certificate Authentication

Replaced plaintext username/password MQTT credentials with X.509 client certificates
signed by a project-owned CA. Each ESP32 now presents a client cert on connect; the
broker rejects any device without a valid CA-signed certificate.

#### `iotgame/mqtt.py` — mTLS support
- `MqttClient.__init__` now accepts `ca_cert_path`, `cert_path`, `key_path` (all optional)
- `_load_file()` reads cert/key bytes from the ESP32 filesystem at startup
- `connect()` builds full mTLS `ssl_params`: sets `CERT_REQUIRED` when CA cert is
  present, attaches client cert + key when both are present
- Falls back cleanly to username/password or anonymous TLS when cert params are `None`
- Log prefix changed from `"MQTT connected"` to `"[MQTT] Connected to host:port"` for
  consistency with other input class logging style

#### `iotgame/device.py` — cert params threaded through
- `IoTDevice.__init__` signature updated: `mqtt_user` and `mqtt_password` are now
  keyword-only with `None` defaults; added `ca_cert_path`, `cert_path`, `key_path`
- All cert params forwarded to `MqttClient`

#### `game/main.py` — backward-compatible cert pickup
- Uses `getattr(config, "CA_CERT_PATH", None)` etc. so old configs without cert fields
  keep working without changes

#### `game/config.py` — cert fields added (commented out)
- Commented-out `CA_CERT_PATH`, `CERT_PATH`, `KEY_PATH` block with instructions
- Current setup remains on port 1883 / no-auth (local Mosquitto)

#### New: `certs/.gitignore`
- Ignores `*.key`, `*.p12`, `*.pfx`
- Allows `ca.crt` and `*/device.crt` to be committed (public material only)

#### New: `scripts/gen_ca.sh`
- Generates 4096-bit RSA root CA, valid 10 years
- Output: `certs/ca.key` (secret) and `certs/ca.crt` (safe to distribute/commit)

#### New: `scripts/gen_device_cert.sh <device-id>`
- Generates 2048-bit RSA key + CSR for one device, signs with CA, cleans up CSR
- Output: `certs/<device-id>/device.key` and `certs/<device-id>/device.crt`
- CN in the cert = `<device-id>` — must match `DEVICE_ID` in `config.py` and the
  ASP.NET device registry

#### New: `scripts/provision_device.py <device-id> [--port]`
- Flashes `ca.crt`, `device.crt`, `device.key` onto ESP32 via `mpremote`
- Validates that `certs/<device-id>/` exists before attempting flash

#### New: `tools/rogue_device.py`
- Demo tool for security presentation — three attack scenarios:
  - `no-cert` — TLS handshake with no client cert; broker rejects at SSL layer
  - `flood` — sends 200 msgs/sec for 5 seconds with a valid-looking device ID;
    server-side rate limiter should quarantine the device
  - `spoof-slot` — publishes to an unknown `slotId` (`inject-admin`); server should
    raise an unknown-slot alert
- Requires a `rogue` device cert (generated separately) for attacks 2 and 3

## Problems Faced

### 1. `IoTDevice` constructor signature conflict
`mqtt_user` and `mqtt_password` were positional in the old signature. Adding optional
cert params after them would have required callers to pass `None` explicitly.
**Fix:** Made `mqtt_user`, `mqtt_password`, and all cert params keyword-only with
`None` defaults. `game/main.py` updated to match; old positional callers would break
but there are none beyond `game/main.py`.

### 2. `ussl.CERT_REQUIRED` varies across MicroPython builds
Not all ESP32 MicroPython firmware includes mbedTLS with full cert verification.
`CERT_REQUIRED` and client cert loading via `certfile`/`keyfile` kwargs require
MicroPython v1.22+ with mbedTLS. Earlier builds silently skip verification.
**Mitigation:** Documented in `docs/plans/phase-6-security.md`. Test on the exact firmware version.
