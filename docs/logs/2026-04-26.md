## Phase 3.1 — DEBUG Flag + DHT11 Auxiliary Humidity

### Problem 1: Noisy serial output in production
All input `tick()` methods printed on every state change. `tick()` runs every 10ms —
any moving joystick or sensor flooded the REPL with hundreds of lines per second, making
the serial monitor unusable and wasting CPU cycles on string formatting.

### Fix: `DEBUG` flag in `config.py`
- Added `DEBUG = True/False` to `config.py` and `config.example.py`
- All "emit" and "raw read" prints in every input class gated behind `if DEBUG:`
- Error prints remain unconditional — always visible regardless of `DEBUG`
- Affected files: `button_input.py`, `knob_input.py`, `sensor_input.py`,
  `dht11_input.py`, `ultrasonic_input.py`

### Problem 2: DHT11 humidity discarded
Phase 3 spec discarded humidity — but DHT11 produces both values from one hardware read.
Discarding humidity wasted a real sensor reading.

### Fix: `auxiliary` field in payload
- `dht11_input.py` now reads and stores both `temperature` and `humidity`
- Event dict includes `"auxiliary": {"humidity": humidity}` alongside `"value": temp`
- `device.py` `_publish_event()` includes `auxiliary` in the MQTT payload when present
- All other input types are unaffected — `auxiliary` is omitted when not in event dict
- Server receives `auxiliary.humidity` and can pass it to Unity as needed

### MQTT payload example (DHT11 after 3.1)
```json
{
  "deviceId": "esp32-stage",
  "slotId": "temp",
  "inputType": "sensor",
  "event": "change",
  "value": 28.0,
  "auxiliary": { "humidity": 65.0 },
  "timestamp": 1234567890,
  "sequenceNumber": 42
}
```

## Phase 3.2 — Design Fix: Swap Temperature and Humidity Effects

**No firmware changes.** The firmware already publishes both values correctly from Phase 3.1.

### Problem
Phase 3 assumed temperature drives spawn rate and humidity was unused. In practice:
- Temperature changes very slowly (10–30s for a meaningful shift) — too slow for a real-time mechanic
- Humidity changes quickly (2–3s from breath or hand proximity) — well suited for immediate effects

### Fix (server/Unity only)
Swap which reading drives which effect in the ASP.NET server and Unity layer.
The firmware `Dht11Input` is unchanged — it already publishes both:
- `value` → temperature (Celsius)
- `auxiliary.humidity` → humidity (%)
