## Phase 2.1 Implementation — Protocol Fix

Separated physical slot identity from semantic input name.

### Problem
`inputName` was used as both a physical slot identifier and a semantic game label.
Two buttons both named `"jump"` for different players caused a collision.

### Fix
- `inputName` removed from firmware entirely — now lives only in ASP.NET registry
- `slotId` introduced as a stable physical identifier (`btn1`, `btn2`, `knob1`, etc.)
- MQTT topic changed: `game/devices/{id}/input/{inputName}` → `game/devices/{id}/slot/{slotId}`
- Config key changed: `"name"` → `"slotId"`
- All input classes renamed `self.name` → `self.slot_id`

### Server-side impact
- Wildcard subscription must update to `game/devices/+/slot/+`
- Device registry maps `(deviceId, slotId)` → `(inputName, playerId)` instead of using inputName from payload

## DHT11 Debugging

### Problem: DHT11 returning 1 or 2 instead of real values
- **Cause:** Missing 4.7kΩ pull-up resistor on data pin + possibly wrong GPIO (ADC-only pins 34–39 unreliable for DHT11)
- **Fix:** Use a regular GPIO (safe pins: 4, 5, 13, 14, 16, 17, 18, 19, 21, 22, 23). Add pull-up resistor between data pin and 3.3V.
- Added `raw read` log line to `dht11_input.py` to surface bad reads immediately
- Set `_last_read_ms = utime.ticks_ms()` on init to delay the first read by `interval_ms`, giving the sensor time to stabilize
